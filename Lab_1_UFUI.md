## **Topic:**

## **Objective:**
1. Закріпити розуміння різниці між UX та UI дизайном.
2. Навчитися аналізувати інтерфейси реальних об’єктів та цифрових продуктів.
3. Розвинути критичне мислення щодо ефективності та зручності дизайну.
## Завдання для попередньої підготовки.
### Короткий словник базових понять:
- User Experience (UX) - досвід користувача, логіка та зручність взаємодії з продуктом.
- User Interface (UI) - користувацький інтерфейс, візуальне оформлення (кольори, шрифти, форми).
- Affordance - властивість об’єкта, що підказує, як ним користуватися.
- Usability - ступінь зручності використання продукту для досягнення цілей.
- Accessibility - доступність інтерфейсу для людей з різними фізичними можливостями.
- Interactivity - здатність системи реагувати на дії користувача.
### Відповіді на питання

#### 1.1.	Дайте визначення поняттю "Інтерфейс".

Інтерфейс - це місце або засіб взаємодії між двома системами, наприклад, між людиною та машиною. Це все, що дозволяє користувачу керувати пристроєм або програмою.

#### 1.2.	Розшифруйте абревіатури UI та UX.

- UI (User Interface) - користувацький інтерфейс (зовнішній вигляд).<br>
- UX (User Experience) - досвід користувача (враження, логіка та зручність).

#### 1.3. Назвіть три основні види інтерфейсів.

- CLI (Command Line Interface) - інтерфейс командного рядка.<br>
- GUI (Graphical User Interface) - графічний інтерфейс (вікна, кнопки, іконки).<br>
- NUI (Natural User Interface) - природний інтерфейс (голосове керування, жести, сенсори).

#### 1.4. Чим відрізняється робота UI-дизайнера від UX-дизайнера при розробці вебсайту?

- UI-дизайнер фокусується на графічній складовій: підбирає шрифти, кольори, малює кнопки, іконки та створює фірмовий стиль бренду. Його задача — зробити візуал красивим та естетичним.<br>
- UX-дизайнер працює над структурою та логікою: проектує шлях користувача від входу до покупки, створює варфрейми (скелет сайту) та тестує, чи зручно людям користуватися продуктом.

#### 1.5. Наведіть приклад "поганого дизайну" з повсякденного життя.

Скляний чайник з красивою металевою ручкою, яка нагрівається настільки, що її неможливо взяти без рукавиці.

#### 1.6. Поясніть принцип "Form follows function" своїми словами.

Це принцип, згідно з яким зовнішній вигляд (форма) предмета має визначатися передусім його функціональним призначенням, а не просто естетикою

#### 1.7. Як поганий UX впливає на технічну частину розробки ПЗ?

Поганий UX змушує користувачів частіше звертатися до техпідтримки, а нелогічні сценарії можуть призводити до помилкових запитів у базу даних.

#### 1.8. Чи може існувати UX без UI?

Так. Наприклад, датчик руху, що вмикає світло: інтерфейсу (кнопок) немає, але досвід (UX) є - світло вмикається вчасно і зручно.

### Відповіді на контрольні запитання

#### 1.	Що спільного між графічним дизайном плаката та інтерфейсом програми?

Обидва спрямовані на створення візуальної структури та графічної складової. Спільним є використання кольорів, шрифтів, ілюстрацій та правильне розташування елементів для того, щоб зробити об'єкт красивим і зручним для сприйняття. У відео UI порівнюється з «презентацією» (зовнішнім виглядом), що є основою і для плакатів.

#### 2.	Чому інженери ПЗ повинні розуміти основи дизайну?

Інженери повинні розуміти дизайн, щоб створювати продукти, які не лише технічно працюють, але й вирішують проблеми користувача. Без розуміння UI/UX програма може бути «незграбною», складною для читання, з кнопками, що не працюють належним чином, що дратуватиме користувачів. Знання дизайну допомагає інженерам реалізувати логічну та комфортну структуру взаємодії.

#### 3.	Наведіть приклад предмета з добре продуманим UX.

Панель приладів автомобіля або контролер відеоігор. Якщо інтерфейс добре спроектований, ви точно знаєте, куди натиснути, не замислюючись про це.

#### 4.	*Ви розробляєте програму для заводу, де робітники працюють у товстих рукавицях. Які обмеження це накладає на UI та UX (розмір кнопок, тип екрану, жести)?

UI: Кнопки мають бути дуже великими, щоб у них було легко влучити пальцем у рукавиці. Кольори мають бути контрастними для кращої видимості в цеху.
<br><br>
UX: Слід уникати складних жестів (наприклад, pinch-to-zoom), замінюючи їх простими натисканнями. Тип екрану має підтримувати роботу в рукавицях (резистивний або спеціальний ємнісний).

#### 5.	*Проаналізуйте інтерфейс командного рядка (CLI). У чому його поганий UX для новачка, і в чому чудовий UX для адміністратора?

Поганий UX для новачка: Немає візуальних підказок (UI), незрозуміло, що робити і які команди вводити. Користувач відчуває розгубленість і розчарування.
<br><br>
Чудовий UX для адміністратора: Це «швидкий шлях» до результату. Досвідчений користувач може виконувати складні операції миттєво, без зайвих кліків, що робить його роботу ефективною.

#### 6.	*Що таке "інтуїтивно зрозумілий інтерфейс"?

Це такий інтерфейс, де користувач знає, куди натиснути, навіть не замислюючись. Він використовує знайомі іконки (наприклад, календар для вибору дати) та просту навігацію, що не потребує навчання.

#### 7.	**Уявіть ситуацію: користувачі постійно помиляються при вводі дати народження на сайті. Як це виправити засобами UI (візуал), а як - засобами UX (логіка)?

UI (Візуал): Додати зрозумілу іконку календаря або використати підказки (placeholder) у полі вводу, щоб показати формат (наприклад, ДД.ММ.РРРР).
<br><br>
UX (Логіка): Спроектувати "шлях користувача" так, щоб замість ручного вводу відкривався випадаючий список або календар, де неможливо ввести неіснуючу дату.

#### 8.	**Як зміна контексту використання впливає на UX? (Порівняйте використання навігатора в телефоні, коли ви сидите на дивані, і коли ви їдете за кермом на швидкості 100 км/год).

На дивані: Користувач має час, може використовувати дрібні елементи та читати довгі тексти.
<br><br>
За кермом (100 км/год): UX має стати максимально спрощеним. Потрібні величезні кнопки, голосове керування та відсутність дрібних деталей, які відволікають від дороги, адже будь-яке ускладнення може призвести до небезпеки.

### Висновок

У ході виконання лабораторної роботи я закріпив розуміння ключової різниці між UX та UI дизайном. На прикладах реальних об’єктів (мікрохвильова піч, молоток) та цифрових інтерфейсів (Instagram) я навчився аналізувати логіку взаємодії та візуальне оформлення продуктів.
<br><br>
Аналізуючи “невидимі інтерфейси”, я зрозумів важливість афордансу - властивостей об’єкта, що підказують спосіб його використання без додаткових інструкцій. Практичні завдання дозволили мені розвинути критичне мислення щодо зручності дизайну: я виявив, як невдале розташування кнопок (як у випадку з оновленням Instagram) може негативно впливати на користувацький досвід.
<br><br>
Отримані знання про принцип “Form follows function” та особливості проектування систем майбутнього (Розумний дім) допоможуть мені в майбутньому розробляти програмне забезпечення, яке буде не лише технічно справним, а й зручним та інтуїтивно зрозумілим для кінцевого користувача.
